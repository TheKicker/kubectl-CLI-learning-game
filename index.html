KUBECTL TRAINING GROUND cases: 0 local time: --:--

Learn kubectl by fixing something that is broken. Each case is one HTML file with a simulated cluster inside it — no install, no network, no real cluster to break.

House rules, and what these do and don't cover

Covered

  • Looking at anything: get, describe, logs, events, top
  • Filtering and pipes: -l app=…, -o wide, | grep -i image:, sort -u
  • Live view: watch -n 1 kubectl get pods -n …
  • Stopping and restarting a Deployment: scale --replicas=0 then 1
  • Reading why something stopped: exit codes, OOMKilled, scale-down events

Not covered in this content… yet

  • edit, apply, exec — changes go live the moment you save
  • delete pods -l … — one typo hits the wrong pods
  • Scaling or deleting a StatefulSet — it holds data
  • Anything in kube-system or monitoring
  • Type one anyway and the game explains what it would do, then stops

Good to know

  • Wrong commands are part of it: near-misses explain themselves
  • Tab completes pod names, ↑/↓ recall history
  • Pod names and timings change every run
  • Each case ends with a cheat sheet and a sample handover
  • Works offline. Nothing you type leaves the page
